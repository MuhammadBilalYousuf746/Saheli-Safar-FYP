# Repository Git workflow

- Keep all project applications and folders in this shared Git repository.
- The first complete-project initial commit is a one-time exception; never commit automatically afterward.
- Before every future commit, list the changed files and explain each file's purpose.
- Ask the user for the commit message and use exactly the message they provide.
- Stage only files the user approves; never stage unrelated files without approval.
- Always request separate explicit permission before pushing.
- Never force-push without explicit authorization.
- Never delete existing project source code or perform destructive Git operations without authorization.
- Never commit credentials, secrets, or environment files.
- Preserve existing project functionality unless a requested change requires otherwise.
